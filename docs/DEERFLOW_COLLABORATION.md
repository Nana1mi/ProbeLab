# DeerFlow 原生大小模型协同展示

已直接修改实际 DeerFlow checkout 的聊天消息渲染器，协同卡片与对话、工具步骤和 Artifacts 并存。卡片不是 iframe，也不要求用户转到独立实验看板。

打开已完成的[真实任务](http://127.0.0.1:3000/workspace/chats/0b6239c6-2655-4769-86a2-a365ee952135)，向上找到“大小模型协同”。

## 界面内容

- 按模型职责分别显示调用数、模型名称、已返回调用的 API 费用；与云端／本地计费路由分开。
- 按时间展示初始验证、小模型探索、并行扩展、大模型 Hint / Solve、依据建议继续探索、采纳方案、停止及独立最终评测。
- 每张卡片可展开实际模型任务、完整输出、提取的候选代码、逐级验证反馈和原始证据。
- 运行期间自动增量更新；关闭或切换对话会中止旧请求。完成后可以重新打开回看。
- 模型文字、代码只作为文本显示，不执行 HTML。完整提示词和证据按需读取。
- 旧实验明确显示“未保存逐次模型输出”，只展示既有决策，不伪造历史候选或大小模型计数。
- Mock 有明确合成数据提示。

## 安装与启动

在本项目根目录执行，参数为现有 DeerFlow checkout：

```powershell
python scripts/install_deerflow_collaboration.py runs/deer-flow-download/deer-flow-3e2489429ff3061489537d7303240fef3f199f83
```

脚本保留原消息渲染逻辑，增加一处组件调用及其 import，安装组件、数据关联逻辑、中英文文案、同源代理及测试；重复执行不会重复注入。适配文件保存在 `integrations/deerflow/frontend/`，不只存在于被忽略的下载目录。

后端仍通过 `scripts/run_deerflow_agent_demo.py` 启动。开发部署将本项目 `src/`、工具客户端、Skill 和生成配置作为只读挂载传入对应容器；研究记录和聊天记录分别保存在命名卷。修改后端 Python 或工具指令后需重新创建对应服务，不能仅刷新浏览器。启动、停止和环境变量见 [集成说明](../integrations/deerflow/README.md)。

查询工具使用最多 120 秒的有界长等待，Agent 指令使用 90 秒，以免长研究反复查询相同状态触发上游循环检测。全局循环检测未关闭。

用户只需提交任务：

> 请优化批量余弦相似度 Top-K 检索算法。在保持结果正确的前提下，尽可能提高运行速度。请实际执行实验，通过自动测试验证，最后给我性能结果、优化过程和实验报告。

## 记录与接口

研究目录新增 `trace.ndjson`，包含逐次模型开始／结束／失败、候选内容、验证结果、控制器决策。只记录任务内容、输出和用量，不序列化 SDK headers、密钥配置或请求异常对象。模型调用记录的 `call_id` 将并行返回、候选和验证对应起来。

`GET /runs/{run_id}/collaboration?offset=0&limit=100` 返回轻量事件分页、按模型职责统计及运行状态；`GET /runs/{run_id}/collaboration/{event_id}` 返回单项完整任务／输出／证据。同源代理沿用 DeerFlow 登录检查和固定上游、路径白名单。当前部署是本机单操作者空间，并不增加多租户隔离。

`summary.small_model_calls` / `strong_model_calls` 来自明确的目标记录。旧账本缺少信息时返回未知，不能把 `cloud_calls` 当作强模型次数。原账本的 Hint / Solve 行可能合并该轮小模型费用；原生卡片使用逐次模型记录拆分费用。

## 真实验收结果

运行 `run_code_tierlab_173ea03f`：小模型 7 次、强模型 2 次（Hint、Solve 各一次）；Solve 方案被采纳，独立最终加速比 **2.0454×**，参考 0.3406 秒、候选 0.1665 秒。研究耗时 193.34 秒；小模型 API ¥0.101506，强模型 API ¥0.009024，合计 ¥0.110530，不含对话模型费用。

最终代码用标准库预计算数据库向量范数并用堆选取 Top-K。这里只证明本次任务得到通过当前测试的提速和可检查的协同过程，没有做同条件单模型基线，不能声称已证明协同比全大模型或全小模型更优。

首次验收对话因短等待反复查询触发上游重复调用限制；后台研究仍正常完成。随后在同一对话查询并展示最终报告，未重跑实验。此问题促成了上述长等待调整，记录保留，未隐藏该事件。新等待逻辑由回归测试覆盖。
