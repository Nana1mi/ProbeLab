## 问题和三个对照组

实现 `topk_cosine_sim(A, Q, k)`，返回每个查询向量按余弦相似度排序的 top-k 数据库下标。统一基准规模：数据库 800 个向量、查询 100 个向量、维度 64、k=5。

| 策略 | 模型与工作方式 |
| --- | --- |
| 小模型单独 | Qwen/Qwen3.6-35B-A3B，每轮根据程序验证反馈改写 |
| 全大模型 | deepseek-ai/DeepSeek-V4.1-Flash，每轮根据相同验证器反馈改写 |
| 大小协同 | Qwen 先写；无提升后请 DeepSeek 给 hint，再由 Qwen 改写；后续可升级 solve |

三组都从同一份参考实现开始。控制器 seed=0、K=1、最多 6 轮、连续 4 轮无提升停止、每组费用上限 1 元、时间上限 600 秒。完整代码输出额度统一为 4096 tokens，hint 为 400。提供商抽样未设置 seed，不保证重跑得到相同文本。

NumPy 对所有组开放。三组统一把原来 50 倍的加速异常上限设为 1000 倍，避免正常 NumPy 实现被拒；保存时钟、父进程耗时交叉检查、正确性检查继续生效。默认项目配置未修改。本结果须用附带实验参数复现。

实验启动前写入的 [manifest](case_studies/code_seed0/manifest.json) 规定保存全部运行，并以超过 10% 且通过新输入复测的性能差异作为代码优势确认门槛。

## 最终冻结代码的复核结果

模型搜索结束后，不再改写或挑选候选，固定每组控制器最终选出的代码。另用 5 个此前未参加搜索的随机输入种子 `20011, 20021, 20023, 20029, 20047`，每组每个输入暖机后重复 31 次，轮换三组执行次序。每次输出都与原参考实现精确比较。

耗时中位数先在每个输入的 31 次测量内计算，再跨 5 个输入取中位数；加速比使用相同输入下参考实现 3 次计时的中位数计算。程序耗时包括函数内部列表转数组等工作，不包括 Python 子进程启动或模型生成。

协同程序的耗时中位数较小模型降低 **12.1%**，较全大模型降低 **13.1%**。按每个相同输入配对计算速度比，协同在五组输入中全部更快，速度提升中位数分别为 16.5% 和 19.7%；该配对统计与两组边际中位数的比值不同。

上表保留两种模型均按 API 收费的原始口径：协同搜索费用较小模型降低 **14.2%**，为全大模型的 **2.16 倍**。费用按仓库配置单价和 API 返回用量估算，非供应商账单。三个代码对照组合计约 **¥0.163536**。搜索调用数并不相同：统一的是轮数上限和停滞规则，协同一轮可能同时调用小模型和顾问。协同最终在第 5 轮因咨询阶梯用完停止；另外两组达到第 6 轮上限。

## 真实协同链条

1. Qwen 首轮生成 NumPy float64 方案，开发评分 76.7003 倍。
2. 第二轮未提升，调用 DeepSeek hint。实际建议包括使用 `np.einsum` 计算范数、`argpartition` 只挑选 top-k，以及考虑 `dtype=np.float32` 并验证排序一致性。
3. 下一轮 Qwen 采用 float32、einsum、矩阵乘法和局部排序，开发评分升至 107.8597 倍，账本归因 `hint_step_2`。
4. 之后的 DeepSeek solve 和小模型重试没有超过该开发分数，最终保留第三轮小模型方案。原控制器单次最终计时为 90.0942 倍；随后冻结复测采用上表的独立重复计时，不能把两种计时口径混用。

## 保留的所有复核与边界

- [第一次隔离子进程复测](case_studies/code_seed0/held_out_recheck.json)：5 个输入，每个候选独立启动，全部正确。程序耗时中位数分别为 4.747、4.022、3.396 ms；其中 seed=9999 是项目最终评估用过的输入，其余四个未用于搜索。
- [第二次暖机复测](case_studies/code_seed0/confirmation.json)：5 个全新输入，每输入 7 次；全部正确，耗时中位数 3.215、2.963、2.757 ms。此阶段对全大模型的优势较小，因此增加固定候选的重复次数确认，未再次调用模型或更换代码。
- [31 次重复确认](case_studies/code_seed0/confirmation_31.json)：主表来源。7 次和 31 次的结果均保留；短至数毫秒的函数计时存在噪声，本报告不提供统计显著性或多次模型搜索胜率结论。
- float32 在本次所有被测随机输入中保持了 top-k 下标一致，但近似相等的相似度、零向量、极端数值等输入仍可能改变排序；该案例不证明任意输入上的全精度等价。
- 本次只有一个任务、一个控制器种子的三组真实搜索，不能外推成协同平均优于两条基线。两种模型都使用云 API，未测量 4090D 的本地推理成本。
- 另外启动过数学探测，仅得到小模型部分输出，代码确认完成后取消；未形成三组对照，不用于本案例结论。相关部分记录见 [数学部分记录](case_studies/math_seed0_partial/)。
